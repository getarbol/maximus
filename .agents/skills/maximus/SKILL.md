# Maximus

A Maximus service is a project. `vite.config.ts` configures it with `maximus()` from `@arbol-ai/vite-plugin`,
and its files declare the rest. A route file declares one operation, its handler and its contract; Maximus
serves it over HTTP with an OpenAPI document, as an MCP tool when the contract names one, and over native
RPC when the contract says so. Each transport admits its caller (an access token holding the operation's
scope, or a Service Binding the service trusts), then every call runs one pipeline: input decoding,
`context.ts`, middleware, the handler, the output check. Work with that pipeline, never around it.

## The project

```text
vite.config.ts                     maximus(): origin, tokens.issuer, env (bindings), compatibilityDate, Worker settings
routes/v1/notes/[noteId].get.ts    GET /api/v1/notes/{noteId}: export default defineHandler(handler, contract)
mcp/tools/summarize-notes.ts       The MCP tool summarize_notes: export default defineTool(handler, contract)
mcp/instructions.md                What MCP clients read when they connect; mcp/guides/ and mcp/skills/ too
context.ts                         export default defineContext(({ env, principal }) => ({ … }))
errors.ts                          export default defineErrors({ … }): the service's own failure codes
auth.ts                            export default defineAuth({ resolve }): tokens the service verifies itself
telemetry.ts                       export default defineTelemetry({ observers }): observers such as analytics()
middleware/                        defineMiddleware (before admission) or defineOperationMiddleware (after it)
pages/ crons/ queues/ email/       Public pages and webhooks (pages/webhooks/x.post.ts), event handlers
durable-objects/                   Durable Object classes, one per file
src/                               Domain code: schemas, stores, clients of other services
tests/                             vp test suites that call handler from #maximus/http in Node
.maximus/                          Generated by maximus prepare: never edit it, never commit it
```

Every file but `vite.config.ts` is optional. [references/project.md](references/project.md) describes
each one.

## Workflow

1. **Read before you write.** Read `vite.config.ts`, `errors.ts`, `context.ts`, the route closest to the
   task and its tests. Keep the project's folders and its named domain functions.
2. **Generate, then fill in.** `bunx maximus gen route <method> <path>` writes a route file, a tool too with
   `--tool <snake_name>`; `bunx maximus gen tool <kebab-name>` writes a tool only agents call. Replace the
   placeholder handler and description, and declare strict `input` and `output` schemas and the
   `failures`. Declare `scope`, `effect` or `operationId` only where the derived one is wrong. See
   [references/routes-and-tools.md](references/routes-and-tools.md).
3. **Scope by organization in the context.** What every handler needs, such as a store, belongs in
   `context.ts`, built from `principal.organizationId`.
4. **Answer failures from the catalog.** `fail(code)` with a code of `errors.ts`, listed in the route's
   `failures`; throw only for what should never happen. See
   [references/errors-and-results.md](references/errors-and-results.md).
5. **Declare bindings in `maximus()`.** `env: { NOTES: bindings.kv() }`, with `bindings` from `cf/config`;
   the generated `Env` types them.
6. **Test** each route in `tests/` through `handler` from `#maximus/http`: its answer, its refusals and that
   one organization never reaches another's data. See [references/testing.md](references/testing.md).
7. **Verify** with `bun run verify` before you finish.

## Commands

| Command                                                         | Does                                                                                                                                        |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun run dev`                                                   | `vp dev`: the Worker in workerd at `http://localhost:5173`. The development token in `.dev.vars` signs in from localhost.                   |
| `bunx maximus gen route get /v1/notes/{noteId} --tool get_note` | Writes `routes/v1/notes/[noteId].get.ts`, which is also the MCP tool `get_note`.                                                            |
| `bunx maximus gen tool summarize-notes`                         | Writes `mcp/tools/summarize-notes.ts`, the tool `summarize_notes`.                                                                          |
| `bunx maximus prepare`                                          | Writes `.maximus/` for production, or with `--mode development` as `vp dev` does. `vp dev`, `vp build` and `vp test` prepare by themselves. |
| `bun run test`                                                  | `vp test run`: the tests, in Node.                                                                                                          |
| `bun run typecheck`                                             | `maximus prepare`, then `tsc`, which also checks type tests.                                                                                |
| `bun run check`, `bun run fix`                                  | Lint and format; with fixes.                                                                                                                |
| `bun run verify`                                                | Types, lint and format, tests and the build. CI runs it.                                                                                    |
| `bun run deploy`                                                | `bun run verify`, then `cf deploy --prebuilt --mode production`.                                                                            |
| `bunx maximus skills`                                           | Links this skill into the project's `.agents/skills`, `.claude/skills` and `.codex/skills`.                                                 |

Every `maximus` command says what it did in a sentence; `--json` prints it as JSON instead.

## Decisions

| Need                                            | Choose                                                                                                                                                                                                   |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An endpoint for people and services             | A route file. Every route is served over HTTP.                                                                                                                                                           |
| The same endpoint for agents                    | `mcp: { name: 'get_note' }` in its contract, which then needs a `description`.                                                                                                                           |
| A capability only agents call                   | A file of `mcp/tools/` with `defineTool`, which needs a `description` and an `effect`.                                                                                                                   |
| Another Worker of the account calls it          | `rpc: true` in its contract and the caller in `maximus()`'s `rpc.callers`; publish a contract the caller imports. See [references/transports.md](references/transports.md).                              |
| Out of the public OpenAPI document              | `visibility: 'internal'`: still routed, still checked against its scope.                                                                                                                                 |
| Setup every call needs: stores, clients         | `context.ts`.                                                                                                                                                                                            |
| A rule for every operation, on every transport  | `defineOperationMiddleware` in `middleware/`.                                                                                                                                                            |
| Headers or an early answer around every request | `defineMiddleware` in `middleware/`. It runs before admission and sees no principal.                                                                                                                     |
| Tokens your authorization server does not issue | `auth.ts` with `defineAuth({ resolve })`, which verifies cryptographically.                                                                                                                              |
| A provider's webhook, without a token           | A page named for its method, `pages/webhooks/<provider>.post.ts`, which verifies the signature on the exact bytes with `@arbol-ai/maximus/webhooks`. See [references/project.md](references/project.md). |
| Many items in one answer                        | `output: Page(Item, { $id: 'ItemPage' })` with `input: PageQueryFields`.                                                                                                                                 |
| A file upload or download                       | `http: { body: 'bytes' }` with `body.read()`; `output: AttachmentOutputSchema` with `http: { response: 'attachment' }`.                                                                                  |
| Data in Postgres                                | `withTenantTransaction` from `@arbol-ai/maximus/postgres`.                                                                                                                                               |
| Guidance agents read over MCP                   | `mcp/instructions.md`, `mcp/guides/<name>.md`, `mcp/skills/<name>.md`: static text for every caller, never tenant data.                                                                                  |
| A 7.x service                                   | [Upgrading to 8.0](https://github.com/getarbol/maximus/blob/main/docs/upgrading-to-8.md).                                                                                                                |

## Rules that are never broken

- **The organization comes from the principal.** Every store, key, query and Durable Object name starts from
  `principal.organizationId`. Never take an organization from input, a header or a path.
- **Schemas are strict.** Inputs and outputs are strict objects or unions of strict objects: fields given as
  `input: { … }` make one; a `t.Object` needs `{ additionalProperties: false }`. A shared entity has a
  PascalCase `$id`. Use the shared schemas (`UuidSchema`, `EmailAddressSchema`, …) rather than copies.
- **Each value is checked once, where it enters.** Maximus checks an operation's input and output; a handler
  never parses its input again. Data from outside the pipeline, such as a stored record, a provider's
  answer or a model's output, goes through `readSchema` or `checkSchema`. No casts, trust flags or no-op
  validators in their place.
- **Failures are declared and honest.** Answer `fail(code)` with a code of `errors.ts`, listed in
  `failures`; the standard failures need no listing. An outage is a failure, never an empty success. A
  write whose outcome is lost answers `OUTCOME_UNKNOWN` and is reconciled, never retried blindly.
- **Exposure is explicit.** A route is a tool only with `mcp` and an RPC method only with `rpc`. Effects,
  `visibility`, descriptions and MCP hints never authorize: scopes and your own checks do.
- **No private data in logs or errors.** Request bodies, input values, credentials, tokens, personal or
  clinical data never go in a log line, a failure's `data` or message, a refinement message, an MCP guide or
  skill, or an example. Report a caught error with `reportUnexpected(error, surface)`, which keeps its name
  and drops its message.
- **Worker code reads `env`, never `process.env`.** A secret is `bindings.secret()`. The development token is
  never declared in `env` and never set on a deployed Worker.
- **Outbound calls:** a Worker's `fetch(…, { redirect: 'error' })` throws before it sends anything. Send with
  `redirect: 'manual'` and refuse a `3xx`.
- **Generated code stays generated.** Never edit `.maximus/`: change the source files or `vite.config.ts`.
- **Refusals are guidance.** `maximus prepare`, `maximus()` and the application's `.build()` refuse a broken
  project with a message that names the rule and the file or operation. Fix the declaration; never loosen
  the check.
